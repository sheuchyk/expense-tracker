# Visual Check Skill

Проверь вёрстку frontend-приложения (Next.js, `expense-tracker`) на десктоп и мобильном разрешении, используя Playwright MCP. Используй после любых изменений в UI (компоненты, стили, layout), чтобы отловить визуальные регрессии до коммита.

## Аргументы

Запрос пользователя: `$ARGUMENTS`

- Если передан путь (например `/login`, `/register`, `/`) — проверь только эту страницу.
- Если аргумент пустой — проверь **все страницы** из списка ниже.

Известные страницы приложения (`frontend/src/app/`):

- `/` — главный дашборд (требует авторизации)
- `/login` — страница входа
- `/register` — страница регистрации

Если в проекте появились новые роуты — найди их в `frontend/src/app/**/page.tsx` перед проверкой.

## Разрешения для проверки

Проверяй каждую страницу в двух вьюпортах через `mcp__playwright__browser_resize`:

| Вьюпорт | Ширина | Высота |
| ------- | ------ | ------ |
| Desktop | 1440   | 900    |
| Mobile  | 390    | 844    |

## Алгоритм выполнения

1. **Убедись, что dev-сервер фронтенда запущен** на `http://localhost:3000`:

   ```bash
   curl -s -o /dev/null -w "%{http_code}" http://localhost:3000
   ```

   Если сервер не отвечает — запусти его в фоне (`npm run dev:frontend`) и подожди старта (проверяй `curl` в цикле, не спи наугад дольше нескольких секунд).

2. Для каждой страницы из списка проверки:
   1. `mcp__playwright__browser_navigate` на `http://localhost:3000<путь>`
   2. `mcp__playwright__browser_resize` → 1440×900 (desktop)
   3. `mcp__playwright__browser_take_screenshot` (сохрани в `.claude/skills/visual-check/screenshots/<slug-страницы>-desktop.png`)
   4. `mcp__playwright__browser_console_messages` — зафиксируй ошибки/warning в консоли
   5. `mcp__playwright__browser_resize` → 390×844 (mobile)
   6. `mcp__playwright__browser_take_screenshot` (сохрани в `.claude/skills/visual-check/screenshots/<slug-страницы>-mobile.png`)
   7. `mcp__playwright__browser_console_messages` — повторно, для мобильного вьюпорта

3. Закрой браузер (`mcp__playwright__browser_close`) после проверки всех страниц.

## Что искать на скриншотах

Ориентируйся на дизайн-язык проекта («Кошелёк»: пастельный дашборд, крупные скругления `rounded-2xl/3xl`, чернильный primary, шрифты Unbounded/Manrope — см. `frontend/CLAUDE.md` и дизайн-токены в `globals.css`/`tailwind.config.ts`).

Проверяй на каждом скриншоте:

- **Переполнение и обрезка** — текст, кнопки или карточки, вылезающие за контейнер (особенно на мобильном 390px)
- **Горизонтальный скролл** на мобильном вьюпорте (признак элемента, не адаптированного под узкий экран)
- **Наложение элементов** друг на друга
- **Разбитые изображения/иконки** — пустые области там, где должна быть иконка
- **Несоответствие дизайн-языку** — синий дефолтный primary вместо чернильного, мелкие скругления, отсутствие пастельных плиток и т.д.
- **Ошибки в консоли браузера** (`browser_console_messages`) — JS-ошибки, 404 на ресурсы, hydration mismatch

## Отчёт

По завершении выведи пользователю краткий отчёт на русском языке:

- Список проверенных страниц и вьюпортов
- Найденные проблемы (с указанием страницы, вьюпорта и что не так) — если есть
- Ошибки консоли, если были
- Если всё в порядке — явно скажи, что регрессий не найдено

Не удаляй сохранённые скриншоты — они пригодятся пользователю для ручной проверки в `.claude/skills/visual-check/screenshots/`.

## Ограничения

- Не изменяй код приложения в рамках этого скилла — только проверка и отчёт.
- Если для проверки нужна авторизация (например, `/` требует логин) и сессии нет — сообщи об этом в отчёте, не пытайся создавать тестового пользователя самостоятельно без явной просьбы.
